# 로컬 연구 환경

현재 2026-10-02 내부 개발판은 미국30·한국30, 기업별 사업 현금 모델31개와 편집 가능한 현금 비교15쌍을 제공합니다. 60개 전체 자유 생성 판독 중 원문 대조 후 검토용으로 펼치는 것은2개이며58개는 보류합니다. 질문 선택60개와 공시 본문 판독60개는 서로 다른 프로토콜입니다. 아래 특정 실행 시점의 수치는 그 당시 기록으로 보존합니다.
2026-09-30 최신 사용자 결정: 외부 AI API를 사용하지 않는다. 공개 공시·가격은 인터넷에서 수집할 수 있고, 추론·분석 기록·화면은 이 프로젝트에 보관한다. 기존 GitHub Pages는 앞서 배포한 공개판이며 새로운 내부 분석을 자동 전송하지 않는다.

## 실행

계산·로컬 판독·후속 조건 관측·오프라인 재현·브라우저·PDF 검사를 함께 실행한다.

```sh
python3 scripts/run-local.py --evaluate
```

CPU 계산과 출력만 재생성하려면 `--skip-model`을 사용한다. 이 경우 보존된 모델 기록 중 근거·규칙 버전이 일치하는 것만 연결한다. 새 모델 판독을 수행했다고 표시하지 않는다. 단계별 로그는 `artifacts/local/runs/<실행시각>/`, 끝까지 통과한 실행의 해시 포인터는 `artifacts/local/last-verified-run.json`이다. 모델의 개발 평가가 실패한 경우에도 그 상태와 보류된 초안을 기록한 사실 보고서를 만들 수 있다. 프로그램·PDF 검사 통과와 의미 평가 결과는 별도다.

현재 조사 대상은 미국 30개·한국 30개다. 공시 계산·과거 추이·기업 비교는 CPU로 처리한다. 기업 전체 GPU 판독은 60개에 별도로 수행하며, 현금·채권 주석 전용 판독 2개와 입력·평가를 구분한다. 사업부 상세 근거는 14개다. 기존 탐색 연구는 초기 8개 기업을 유지한다.

통합 실행은 기업·기준 회계기간별 현금 마진 조건과 채권 부담 조건을 한 번 등록하고 후속 공시를 관측한다. 현재 현금 61개(Ford의 과거 기간 조건 포함)·채권 2개이며 반복 실행이 기존 등록의 기준선·해시를 바꾸지 않는다. 수동 등록은 `python3 -m equitylab register`와 `python3 -m equitylab register-receivables`, 후속 관측은 `python3 -m equitylab observe`다. 채권 조건은 두 시점 평균 대용일수의 전년 동기 차이가 0일 이하인지 확인하며, 결측·정의 변경·통화 불일치는 미확인으로 남긴다. 등록한 방향 예측이 없어 적중률을 만들지 않는다. 신용 악화 여부는 이 조건으로 자동 판정하지 않는다.

Codex 샌드박스 안에서 Chrome이 `setsockopt: Operation not permitted`로 중단되면 샌드박스 밖 실행 권한이 필요하다. 일반 로컬 터미널에서는 별도 웹 서버를 설치하지 않는다. 통합 실행은 같은 명령의 동시 실행을 잠금으로 막고, 모델 포트나 GPU가 다른 작업에 사용 중이면 해당 작업을 중지하지 않는다.

저장된 공시로 다시 계산하고 로컬 모델의 가설·반론을 생성한다.

```sh
python3 scripts/local-research.py --recalculate --evaluate --model qwen3:8b --thinking
```

처음 또는 모델·규칙·설정을 바꾼 뒤에는 위 `--evaluate`를 포함한다. 설정이 같은 이후 공시 갱신에서는 `python3 scripts/local-research.py --recalculate`로 기존 평가를 재사용할 수 있다. 현재 기본 모델은 Qwen3 8B이며 숙고를 켠다. `--model qwen3.5:9b --no-thinking`은 별도 평가가 필요한 비교 설정이다.

계산만 다시 하려면 `python3 -m equitylab refresh --as-of 2026-09-29`를 실행한다. 기준일은 확보한 자료에 맞게 정한다. 새 공개 자료를 수집할 때만 기존 `refresh --online`과 `sync-history`를 사용한다. 한국 기업을 포함한 `--online` 갱신은 DART 키가 없으면 수집 전에 중단한다. 키는 환경 변수 또는 `--dart-env`로 제공하며 모델 추론에는 어떤 외부 API 키도 필요 없다.

화면은 `app/index.html`을 브라우저에서 직접 열면 된다. 필터·현금 분해·가격 가정·모델 검토 기록은 정적 파일 안에서 동작한다. 모델은 배치 실행 중에만 프로젝트 전용 loopback 포트 11435로 실행되고, 작업 종료·실패 시 종료된다. 상시 웹 서버나 외부 AI 호출을 요구하지 않는다.

## 기업 전체 판독과 전향 관측

```sh
python3 scripts/local-coverage.py --evaluate --resume --wait-gpu-seconds 3600
python3 -m equitylab register-study
```

첫 명령은 현재 60종목의 매출·현금·재투자, 확보된 사업부·리스 근거에서 가능한 설명·대안·구별 질문·공백을 작성한다. 숫자는 코드가 계산하며 가설에 관측의 원문을 연결한다. 기본은 Qwen3 8B, 숙고 켬, 컨텍스트 8192, temperature 0.6, top_p 0.95, top_k 20이다. 현행 v12 생성 지시는 미확인 자료에서 경쟁 설명을 세우고 추가 관측으로 구별하는 연구 질문을 요청한다. `--no-thinking`은 별도 평가가 필요한 비교 설정이다. JSON 문자열의 넓은 정규식 제약에서 실제 응답 형식 실패가 있어 v5는 길이 제한과 생성 후 숫자 검사를 분리한다. 기업 전체 판독은 `OLLAMA_GO_TEMPLATE=0`으로 GGUF의 Jinja 템플릿을 사용한다. 기존 Go 템플릿 경로에서 관측한 형식 실패 기록을 보존했고, 새 경로는 `--probe-format`의 상수 및 실제 기업 네 문장 출력 제약 검사로 확인한다. 모델·입력·프로토콜·추론 설정이 일치할 때만 `--resume`이 이전 기록을 재사용한다. 다른 작업이 GPU를 쓰면 지정 시간 동안 기다리며 종료시키지 않는다.

`data/coverage-evaluations/`는 채권 전용 평가와 별도로 보존한 합성 개발 평가다. 개발 기준 미충족이나 문장 비판이 남으면 기업 가설을 접어서 표시한다. 실행 실패와 원응답도 `data/coverage-reviews/`에 남긴다. 종료 코드 2는 보류·실패가 있는 실행이며 자동 해석 승인을 뜻하지 않는다.

`data/forward-study.json`은 최초 실행에서 한 번 고정된다. 같은 명령을 다시 실행해도 대상을 바꾸지 않는다. 입력일은 현지 등록일보다 앞서야 하며 진입은 등록일 이후 첫 관측 거래일이다. 다음 자료 갱신 때 동일 대상의 21·63거래일 결과를 평가한다. 빠진 기업을 제외하거나 관측 날짜를 옮기지 않는다. 사전 관측 계획이 존재하는 것과 미래 성과가 입증된 것은 다르다.

## 모델과 저장 위치

- `.local/ollama/`: 프로젝트 전용 Ollama 실행 파일·라이브러리 사본
- `.local/models/`: 필요한 모델 manifest와 digest를 대조한 가중치 사본
- `.local/tmp/`: 추론 임시 파일. 루트 디스크 대신 프로젝트의 20TB 파일시스템 사용
- `data/local-reviews/`: 입력·실제 출력·실패 기록·검토 결과. 새 실행은 새 디렉터리에 저장
- `data/local-evaluations/`: 실행 전 고정한 합성 예문·프로토콜·문장별 결과·중단 기록
- `artifacts/local/`: 런타임 로그와 실행 영수증

현재 환경은 RTX3070 8GB이다. 프로젝트 밖의 Ollama11434와 원본 모델·서비스 설정을 변경하지 않는다. 시작 시 이미 GPU 메모리가 사용 중이면 실행을 보류하며 다른 작업을 강제 해제하지 않는다. 작업을 동시 실행하지 않는다. 이 확인은 서로 다른 프로젝트 전체를 잠그는 전역 스케줄러는 아니다.

다른 컴퓨터에서는 로컬 Ollama 배포본을 `.local/ollama/`, 필요한 모델을 `.local/models/`에 준비해야 한다. 이 프로젝트는 모델을 자동 내려받거나 외부 모델로 대체하지 않는다. 인터넷이 없는 환경에는 실행 파일·모델·공시 사본을 반입할 수 있다. 모델의 라이선스와 실행 플랫폼을 확인한다.

### 인터넷 없이 다른 경로에서 실행

연구 ZIP에는 공시·가격·코드·모델 원응답과 Python 설치 파일을 넣는다. `artifacts/local/offline-wheels/`와 `requirements-offline.lock`은 **Linux x86_64 / Python 3.12**용 16개 배포 파일의 버전·SHA-256을 고정한다. 기존 PC의 전역 패키지를 사용하지 않는 가상환경에서 다음과 같이 설치한다. 다른 플랫폼은 해당 플랫폼의 설치 파일이 필요하다.

```sh
python3.12 -m venv .local/python
.local/python/bin/python -m pip install --no-index --require-hashes \
  --find-links artifacts/local/offline-wheels -r requirements-offline.lock
.local/python/bin/python start.py status
.local/python/bin/python start.py open
```

저장된 화면은 모델 없이 열린다. 새 GPU 판독에는 별도 `equity-gpu-linux-x86_64-*.tar`를 **연구 ZIP을 푼 폴더 안에서** 해제한다. 이 묶음은 프로젝트 Ollama와 실제 사용한 Qwen3:8B의 가중치·템플릿·라이선스만 포함하며, `GPU-BUNDLE-MANIFEST.json`에 각 파일 해시가 있다. 호환 NVIDIA 드라이버는 실행 PC에 설치돼 있어야 한다. 그 뒤 `.local/python/bin/python scripts/local-filings.py --resume`으로 현재 입력과 일치하지 않는 판독을 실행한다. 이 환경에 맞는 묶음은 `python3 scripts/prepare-runtime.py`로 재생성한다.

전체 브라우저·PDF 검사에는 Chrome 131 이상·Node.js·Noto CJK 글꼴도 필요하다. 실제 검증은 Chrome 147에서 수행했다. 인쇄 버전·쪽수는 본문과 겹치지 않도록 [Chrome의 페이지 여백 상자](https://developer.chrome.com/blog/print-margins?hl=en)에 출력하며, 검사에서 지원 여부와 모든 페이지의 본문·하단 표식 간격을 확인한다. 이 시스템 패키지는 Python 설치 파일이나 GPU 묶음에 포함하지 않는다. 화면 열기·저장본 분석, 새 모델 판독, 브라우저 자동 검사의 설치 범위를 구분한다.

## 해석과 검증

Micron·SK하이닉스에는 기초·기말 순매출채권, 대용일수 두 정의, 충당금(확보된 경우), 공시 정책과 남은 공백을 추가로 제공한다. SEC 숫자는 companyfacts, 경영진 설명은 별도로 보존한 10-Q HTML, DART는 연결 XBRL 컨텍스트에서 읽는다. 별도 재무·거래처·부문 컨텍스트를 섞지 않는다. 전년 잔액을 다른 과거 공시에서 보완할 때 제출일과 접수번호를 유지한다. 입력이나 정책 설명이 달라지면 이전 모델 판독도 보류한다.

프로그램이 연결 범위·기간·단위·부호·현금 조정·전년 변화를 계산한다. 매출·채권 현금 효과·영업현금의 당기와 전년 수치를 함께 제공한다. 근거 ID는 프로그램이 연결하며 모델에게 선택시키지 않는다. 모델은 가능한 설명, 경쟁하는 설명, 두 설명을 구별할 다음 관측, 현재 입력의 근거 공백을 각각 한 문장으로 작성한다. 금액·비율·연도를 문장에 새로 생성하면 거부한다.

반론 모델은 각 문장을 정확히 인용하고 supported / conditional / unsupported / contradicted / unresolved로 분류한다. 관측과 근거 공백은 supported, 가설·대안·확인 질문은 conditional만 허용한다. 다른 문장을 대신 지적하거나 문장을 누락·중복하면 거부한다. 문장별 분류가 맞다는 독립 보증은 아니며, 같은 모델의 오류가 두 번 반복될 수 있다.

같은 모델의 두 번 읽기는 독립 검토가 아니다. 근거 ID가 존재한다는 검사만으로 문장의 인과 해석을 승인하지 않는다. 수정 필요·실패·자료 변경 후 보류 상태를 남긴다. 원문 사실과 모형의 가능한 설명을 구분한다.

Micron은 공시 현금흐름표의 순이익·감가상각·주식보상·자산/부채 변동·기타 항목을 연결한다. SK하이닉스는 주석의 연결·보고금액 맥락에서 평가손익·세금·채권·재고 등을 읽으며 미분해 잔액을 따로 남긴다. 잔액의 존재를 숨기거나 모두 운전자본으로 이름 붙이지 않는다.

가격 화면은 공시 보통주 수와 관측 종가의 근사 주식가치를 설명하는 데 필요한 배분 가능 현금을 역산한다. 공시 이후 희석·소각과 정상 이익은 미확인이다. 공시 CFO−설비취득을 FCFE로 간주해 할인하지 않으며 목표가를 내지 않는다.

## 채권 전용 판독 개발 평가

`--evaluate`는 기업 초안을 쓰기 전에 합성 예문을 점검하고, `--evaluation-only`는 예문만 실행한다. `data/evaluation/local-claims-v1.json`은 허용 문장 여덟 개와 오류 문장 여덟 개를 포함한다. 실행 전에 파일 전체·해시·모델 digest·샘플링 설정·판독 규칙을 보존하고, 정답과 정답 이유는 모델 입력에 보내지 않는다.

사전 기준은 오류 문장 허용 없음, 허용 문장 거부 한 개 이하, 형식·실행 실패 없음이다. 모델이 확정 문구를 가설로 잘못 허용한 개발 오류를 보고, 가설·대안에는 명시적 유보 표현이 있어야 한다는 필요조건을 추가했다. 모델 단독 판정과 문장 형식 조건을 합친 판정을 따로 기록한다. 이 조건은 문장 의미의 진실성을 증명하지 않으며, 같은 개발 예제로 수정한 규칙의 회귀 점검이다. 실행 실패 시 나머지 고비용 호출을 중단하고 미완료로 남긴다. 일부 문장만 실행한 결과를 전체 통과로 표시하지 않는다. 문장별 결과는 즉시 progress.jsonl에 쓰며, 불완전·잘못된 JSON도 파싱 전에 원응답을 보존한다. 실패·중단한 실행을 삭제하거나 마지막 정상 기록으로 위장하지 않는다.

모델·추론 설정·판독 규칙·예문 해시 중 하나라도 다르면 평가를 재사용하지 않는다. 평가가 없거나 미충족이면 기업 문장이 자체 점검을 통과해도 UI에서 보류한다. 같은 개발 예제에서 여러 설정을 비교했으며 금융 정확도나 표본외 검증을 뜻하지 않는다.

Qwen의 greedy/temperature=0 숙고 실행은 반복·시간 초과를 보였다. 샘플링은 모델 제작사의 권장 설정을 기준으로 하며 사용한 값은 각 request와 evaluation.json에 보존한다. [Qwen3 권장 설정](https://huggingface.co/Qwen/Qwen3-8B), [Qwen3.5 권장 설정](https://huggingface.co/Qwen/Qwen3.5-9B), [Ollama 숙고 설정](https://docs.ollama.com/capabilities/thinking). Qwen3.5의 숙고 모드는 이 환경에서 출력 예산 초과를 보여 운영 기본값으로 삼지 않는다.

판독 기록은 숫자 분석과 별도 사건이다. PDF 검사는 분석 해시뿐 아니라 화면 데이터 전체와 로컬 검토 기록 해시도 대조한다. 판독을 다시 실행했다면 `check-live.mjs`와 `check-artifacts.py`를 다시 실행해야 한다.

## 조사 질문 선택과 자유 생성의 분리

`python3 scripts/local-questions.py --resume --wait-gpu-seconds 3600`은 Qwen3:8B 숙고 켬으로 현재 기업의 공시·사업부·가격 가정·동종 차이를 읽고 적용 가능한 연구 설계 두 개의 ID를 선택한다. 해석 문구는 사전에 명시한 설계다. 선택 결과와 입력·원응답·GPU·모델 해시를 `data/question-selections/`에 보존하며 입력이나 프로토콜이 바뀌면 과거 선택을 최신으로 쓰지 않는다. 생성 실패는 임의 기본 선택으로 대체하지 않는다.

이 절차는 자유 생성에서 반복된 회계·인과 오류의 노출 범위를 줄인다. 선택이 올바른 범위인지와 원응답이 같은지를 검사하지만 어떤 질문 순서가 실제 연구나 투자에 더 유용한지는 아직 평가하지 않았다. 기존 자유 생성 v12 개발12·별도24의 판독 평가는 이 선택기의 정확도 평가가 아니다. 기존 가설·비판·수정·오류 보류 기록은 계속 확인할 수 있다. 통합 실행은 두 절차를 실행한 뒤 공통 화면과 PDF를 만든다.

이전 질문 선택 v1은40기업 전부 실제 GPU에서 완료했다. 우선 질문은 가격 조건26·증권 권리6·금융 범위4·현금 전환4였다. 중복 선택·적용 불가 ID·형식 실패는 없었다. 기록별 총 추론 시간의 합은 약487초이며, 동일 입력3건을 재사용한 전체 배치 기록은 `artifacts/local/question-run-20260930T135057592720Z.json`이다. 이것은 범위·형식·실행 결과이고 질문 선택의 금융적 우월성은 평가하지 않았다. 종료 후 전용11435포트가 닫혔고 GPU는2MiB/0%로 돌아왔다.

질문 설계 v2에서 현금흐름 분류 설명을 정정했다. 배당을 일괄적으로 영업현금에서 제외하던 작성자 문구를 삭제하고, 적용 기준과 해당 공시의 실제 분류를 확인하도록 바꿨다. [IAS 7 공식 문서](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2024/issued/part-a/ias-7-statement-of-cash-flows.pdf?bypass=on) 문단31–34에는 이자·배당 분류 선택이 있으며 이후 기준 개정·조기 적용 여부도 확인해야 한다. 기존 v1 기록과 당시 압축본은 이전 버전으로 보존하고 최종 배포 대상으로 쓰지 않는다. 자유 생성 v12의 프로토콜·계산식은 변경하지 않았다.

반복 실행에서도 선택을 확정된 우선순위로 읽지 않는다. v1→v2 재실행에서 NVIDIA의 요청 JSON·모델 digest가 완전히 같았지만 두 번째 질문이 투자 목적에서 현금 전환으로 달라졌다. 원응답을 보존하며 seed 설정을 결과의 비트 단위 재현 보증으로 표시하지 않는다. 수치 계산의 오프라인 재현과 모델의 반복 생성 안정성은 별개다.

이전 질문 설계v2의40기업 실행은 `artifacts/local/question-run-20260930T141051132072Z.json`에 완료했다. 두 버전의 요청이 같았던40기업 중1기업의 선택이 달랐으며, 기술적 반복 비교는 `question-selection-repeat-comparison.json`에 보존한다. 최종 분석`bdefb044e2ab`의 통합 실행`20260930T141933971392Z`에서 단위138·원문183 재현·브라우저132·PDF8개82쪽 검사가 통과했다. 모든82쪽을 재확인했고 현금흐름 분류 정정 문구를 실제 PDF에서도 확인했다.


## 공시 본문 판독과 작성자 대조

`python3 scripts/local-filings.py --resume --wait-gpu-seconds 3600`은 60개 기업의 `reading-seeds.json`에 지정된 실제 문단을 읽는다. 본문을 빠짐없이 심사하는 모델은 아니며, 공시 접수·본문 해시가 바뀌면 문단 선정부터 갱신해야 한다. 인용문은 프로그램이 직접 붙이고, 모델은 문단 ID와 한국어 해석·조건부 함의·다음 질문을 생성한다. 원문에 같은 숫자가 있어도 기간·단위·계산 대상이 맞는지는 별도다.

v3는 60개 초안 생성과 KT 원문 단위 보강 후 재판독을 완료했고 작성자 대조에서 55개 수정 필요, 5개 큰 사실 충돌 미발견으로 기록했다. 이는 독립 정확도 평가가 아니다. `data/filing-reading-audits.json`은 모델 기록 해시·대상 문장·이유를 보존하며 `filing_reading.py`가 정확한 원문과 연결한다. 이 감사는 기존 기업 전체 판독 v12 및 채권 전용 판독의 평가와 별개다. 화면은 검토 지적을 보여주고 원 생성문을 보존한다.

영어 공시를 영어로 답하게 한 별도 세 사례 개발 비교는 `artifacts/local/filing-language-comparison.json`에 있다. 일부 단위·대상 구분이 나아졌으나 기간·인과 오류가 남아 기본 판독으로 채택하지 않았다. `--language-probe --company MU --company AMZN --company F`는 실험 출력만 저장하며 회사별 최신 모델 기록·화면을 바꾸지 않는다.

이전 12모델 확장 시점에는 60개 본문·사업 해석과 18쌍의 원문 비교를 연결했습니다. Alphabet·Meta와 Micron·SK하이닉스를 포함하고 NVIDIA·AMD와 Apple·삼성전자까지 6쌍에서는 두 회사의 정확한 현금 가정을 함께 편집합니다. KT는 긴 문단 색인에서 생략된 짧은 단위 표제를 원 XML의 인접 표에서 별도 대조해 모델 입력과 화면에 보존합니다.


통합 실행은 새 추론 요청을 보내기 직전에 기본 600초까지 다른 계산 작업이 끝나기를 기다립니다. 설치 모델의 해시 확인과 기존 판독의 재사용에는 GPU를 기다리거나 적재하지 않습니다. `--wait-gpu-seconds 0`은 즉시 보류하고, 양수는 최대 대기 시간을 지정합니다. 작은 GPU 메모리 사용량도 계산 프로세스가 남아 있으면 빈 GPU로 간주하지 않습니다. 다른 프로젝트의 모델을 내리거나 서비스를 정지하지 않습니다. 재사용되는 기업 판독은 화면을 마지막에 한 번 갱신하고, 새 판독만 완료 즉시 갱신합니다.
