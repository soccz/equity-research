# 사용자 감사에 대한 정정과 우선순위

**후속 정정:** 사용자는 기존 report를 확장하는 것이 아니라 이 폴더에 독립 프로젝트를 만드는 의도임을 확인했다. 아래는 감사 당시의 확인·판단 기록이다. 분석 단위·통계·실제 운영 상태의 정정은 유지한다. report persona의 자동 상속, 한국 top30 원장으로의 범위 축소, 일정 연기는 이 프로젝트에 적용하지 않는다. 외부 권고를 사용자 확정 결정처럼 취급한 판단을 바로잡았다.

2026년 9월 30일 13시대 KST 읽기 전용 확인. 자료와 운영 상태가 다른 세션에서 바뀌고 있으므로 아래 시점 이후의 변화는 다시 확인한다.

감사 당시 통합 플랫폼 화면 작성을 중단했으며 데이터·CSS만 미완성 상태였다. 이후 사용자의 독립 프로젝트 확인과 계속 진행 지시에 따라 네 화면의 설계 미리보기, 계산, 브라우저 검증과 PDF 예시를 구현했다. 현재 상태는 [README](../README.md)를 기준으로 읽는다. 실제 기업의 공시·가격 연결과 추천 검증은 아직 없다.

## 정정

- 앞선 답변에서 인용한 개선 폭은 종목 단위 예측 정확도가 아니다. 종목 예측을 합산한 **WML 포트폴리오 분산의 QLIKE**를 기준 모형과 비교한 결과다(구체 수치는 비공개 졸업논문 판정서에 있다). 종목 단위 표본외 정확도로 주장한 것은 오류다.
- 같은 표에서 인용한 유의확률은 **Sharpe 차이**의 검정이다. QLIKE 차이의 DM 검정은 별도 열로 보고돼 있다. 이미 본 표본의 탐색 결과이고 모형 전체에 대한 다중검정 보정은 하지 않았으므로 개별 주식 효과나 확인적 성공으로 확장하지 않는다.
- report의 persona는 3년 사업체 관점이며 목표가·매수/매도 권고·1년 미만 예측을 제한한다. report를 확장하는 v1에서 기존 통합 설계의 6–12개월 의견 등급을 그대로 채택하지 않는다.
- report의 `condition_fulfillments`는 현재 코드에서 0으로 설정돼 있다. 조건 성립의 전향 채점 기능이 구현됐다고 주장하지 않는다.
- xsec 60창 전향 실험은 `inconclusive`다. paired +0.5003711%p, CI95 [−0.2351158, +1.3182866]%p이며 실제 체결 수익은 평가하지 않았다. 이는 edge의 부재 입증이 아니라 해당 실험에서의 개선 근거 미확보다.
- 미국 운영 데이터 연결과 역사 연구자료의 존재를 구분한다. 역사 CRSP 검증 자산은 존재하지만 최신 미국 공시·가격·옵션 서비스가 연결돼 있다는 근거가 아니다.

임시 자료 후보는 `/tmp/mlj_paper02_complete_20260910` 3.68GiB, `/tmp/orx-strict-audit.S79Q9M` 2.15GiB, `/tmp/openresearch-cli-audit` 1.44GiB, `/tmp/ecoguard-public-fixture-cache` 1.10GiB로, 합계 약 8.37GiB다. 오래된 이름이나 수정 시각만으로 안전한 삭제 대상으로 확정하지 않았다. 일부 시스템 디렉토리는 권한 때문에 읽지 못했으므로 전체 사용량의 원인을 다 확인했다고 주장하지 않는다. 접근 가능한 프로세스에서 100MiB 이상인 루트의 삭제된 열린 파일은 발견되지 않았으며, 모든 사용자 프로세스에 대한 증명은 아니다.

xsec MEMORY의 13:11 복구 기록과 현재 systemd 결과가 일치한다. 사용자가 별도 디스크를 필수로 하지 않기로 결정하여 20TB 작업 디스크의 검증된 사본으로 전환한 상태다. 디스크 고장 보호와 동일 디스크 복원 사본은 구분한다. 과거 실패 기록은 보존한다.

사전등록 기준 3의 실제 문구는 FREEZE/LIQUIDATE 무발동 뒤에 **발동 시 사유 해소 증빙 필수**라는 예외가 있다. 발동 기록만으로 최종 KILL을 단정하지 말고, 예외 충족 증빙과 이후 사용자의 운영 결정을 대조해야 한다. 과거 09-01 판정과 09-07 시작한 60창 실험은 다른 계약이다.

이 세션에서 서비스 중지, 디스크 삭제·이동, report 커밋·원격 푸시를 수행하지 않았다. 원격 백업의 부재는 Git 미추적 사실만으로 모든 별도 백업 경로까지 입증한 것은 아니다.

## 판단 조건 원장을 채택할 때 필요한 수정

한국 top30의 기존 보고서에 한정해 조건을 사전에 고정하고 후속 공시로 확인하는 범위는 적절한 다음 검토안이다. 다만 조건과 예측을 별도로 정의해야 한다.

예를 들어 매출채권 회수가 개선되면 판단을 상향한다는 조건은 회수가 개선될 것이라는 예측이 아니다. 개선되지 않았다고 원래 판단을 오답 처리할 수 없다. 원장에는 다음을 따로 기록한다.

1. 원래의 기업 판단과 근거.
2. 판단을 바꿀 조건과 기계적으로 계산 가능한 판정식.
3. 해당 조건이 성립할 것이라는 사전 예상이 있는지 여부와 예상값 또는 범위.
4. 비교 기준선과 기준선이 사용하는 정보.
5. 실제 관측, 조건 성립 여부, 예상 오차, 판단 변경의 실행 여부.

원문의 회사·연결 범위·단위·정정 여부가 맞고 같은 정의의 수치가 있을 때만 분기를 차감한다. 4분기 단독 영업현금흐름은 연간 누적에서 9개월 누적을 빼는 계산이므로 양쪽 자료의 정합을 확인해야 한다. 공시가 없거나 비교 불가능하면 자료 부족이다.

3분기 역시 9개월 누적에서 6개월 누적을 빼는 설계가 가능하다. 4분기를 선택하는 근거는 논문 일정과 충분한 사전 고정·자료 준비 기간으로 제시해야 하며, 누적 수치라는 이유만으로 3분기 검정이 필연적으로 무의미하다고 단정하지 않는다.

해시는 내용 변경을 검출하지만 사전 기록 시점을 독립적으로 증명하지는 않는다. 최초 관련 정보가 공개되기 전에 기록됐는지 확인할 수 있는 타임스탬프와 버전 이력이 함께 필요하다. 고정 후 공개 정보를 이용한 해석 수정도 원본과 별도 버전으로 남긴다.

제안된 11월 착수, 12월 말 조건 고정, 다음 해 4월 첫 채점 일정은 아직 사용자 확정 일정으로 기록하지 않는다. 이 폴더에서 타이머·자동 채점을 설치하지 않았다.
